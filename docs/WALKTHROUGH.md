# A 90-second recording guide

Record the actual running interface. Do not claim real customers, time savings, measured AI accuracy or external delivery. Start in offline/preview mode with an empty or clearly identified example conversation.

| Time | Show | Suggested narration |
|---|---|---|
| 0–12 s | Customer view; Ask in Slovenian | “This is a fictional bike workshop. A customer can ask a price question in Slovenian and see the approved source.” |
| 12–28 s | Custom repair; submit details | “A custom repair needs a mechanic, so the assistant passes the question and conversation together.” |
| 28–43 s | Workshop desk; expand transcript; edit draft | “Staff get the context and an editable reply. In this offline preview it's a labelled template. Nothing is sent before approval.” |
| 43–58 s | Pause delivery; approve; show recorded failure | “If delivery fails, the approved message stays saved. This is an actual n8n run, with retries and a recorded execution.” |
| 58–70 s | Restore; retry; preview inbox | “Restore the connection and retry the same job. It keeps the original message identity rather than creating another reply.” |
| 70–83 s | Change full-service price; ask again | “The owner can update approved facts without a developer or a deployment. The next answer uses the new version.” |
| 83–90 s | Proof & connections | “The project shows what was verified and which external connections still need account setup.” |

If n8n's retry delay takes longer than the allotted shot, use a clearly visible cut. Do not disguise a cut as a measured response time. The automated verification is a separate acceptance check, not an accuracy benchmark.

Optional second clip: advance the labelled demo clock, show a follow-up draft, then send a customer reply and demonstrate that stale approval is blocked.
